# Esnad

Arabic semantic search engine for Saudi commercial court judgments using BGE-M3 and FAISS.

## Run the search interface

```bash
python -m pip install -r requirements-ui.txt
streamlit run esnad_final_ui.py
```

## ALARB: publish the 6000-judgment release

The search engines select the ALARB index and metadata from
`artifacts/alarb/alarb_search_config.json` using its `number_of_cases`.
The existing 200-judgment release remains active until the complete new set is published.

For 6000 judgments, publish these **three files together** under `artifacts/alarb/`:

- `alarb_judgments_6000.index`
- `alarb_judgments_metadata_6000.parquet`
- `alarb_search_config.json` with `"number_of_cases": 6000`

Both search engines validate the configured count against the index and metadata,
check the embedding dimension and unique case IDs, and refuse an incomplete or mixed release.
Uploading a pipeline notebook alone does not publish its generated artifacts.

The files generated by the pipeline are in Google Drive at
`MyDrive/Esnad/final_artifacts/`. A notebook checkpoint or a saved embeddings array
does not need to be uploaded to run the search engine.

[Open the upload notebook in Colab](https://colab.research.google.com/github/raghad-cs/Esnad/blob/upscaling/notebooks/upload_alarb_6000.ipynb)

Run its three code cells from the Google account holding the generated files.
It validates the real files without loading BGE-M3, clones a fresh copy of
`upscaling`, copies only the three ALARB artifacts, commits them together and pushes
without force. Enter a token only in the hidden prompt, using the same GitHub account
as the username. The account/token must have write access to this repository.
The repository owner can use a fine-grained token restricted to Esnad with Contents
read/write. A collaborator using a different personal account currently needs a
classic token with the public_repo scope for this public repository; fine-grained
tokens do not support writing to another user's repository. See
[GitHub's token limitations](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).
No credentials are written to the notebook, the repository, or Git's credential store.

GitHub's browser upload limit is 25 MiB per file, while regular Git accepts files
up to 100 MiB. The saved outputs (approximately 23.44 MiB and 26.76 MiB) fit Git's
limit, so this release does not require splitting the data.
See [GitHub's file limits](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).

This only updates `upscaling`. A deployment must use this branch/release
(or receive a reviewed merge) before the running site changes.

## Loader checks

```bash
python -m unittest discover -s tests -v
```

These tests use synthetic metadata and mocked binary readers/model calls to check
release selection and reject missing or mismatched artifacts. The Colab uploader
also reads and validates the real FAISS and Parquet files before publishing them.
